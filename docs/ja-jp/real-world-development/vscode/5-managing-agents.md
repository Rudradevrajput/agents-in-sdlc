GitHub Copilot をエージェント モードで使うと、コードベースを調べ、変更を提案し、ファイルを編集し、コマンドを実行します。VS Code の Copilot Chat は、作業がローカルでリアルタイムに進むため、ツール呼び出しやファイル編集を逐一表示します。差分を確認し、個々の変更を受け入れるか元に戻し、エディターを離れずに追加プロンプトを送って作業を調整、拡張できます。

この演習では、次の操作を行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して受け入れます。
- セッション中にエージェントを誘導し、ハイ コントラストに加えてライト モードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントは、ハイ コントラスト モードを実装しています。作業中、デザイン チームから、既定のテーマが暗すぎると感じる利用者向けにライト モードも追加してほしいという要望がありました。新しい会話を始める代わりに、既存のセッションを誘導して作業を拡張します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集などの各手順が表示されます。ファイル編集は差分と **Keep** / **Undo** 操作とともにチャットに表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求められたターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分が表示されます。
   - **Keep** を選択すると変更を受け入れます。
   - **Undo** を選択すると変更を元に戻し、エージェントに再度作業させます。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイル全体を確認できます。

> [!NOTE]
> ターミナル コマンドの実行などに許可が必要な場合、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可してもよいコマンドだけを承認してください。

5. エージェントがハイ コントラスト モードの実装を終えるまで待ちます。最終メッセージに変更の概要が表示されます。

## エージェントにライト モードを追加させる

ハイ コントラスト モードができたので、同じ会話でライト モードの切り替えも追加します。同じセッションを続けると、エージェントは変更したコンポーネント、スタイルの方針、local storage の使用方法など、前の作業のコンテキストを保持します。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を確認してから、ライト モードの追加を提案します。
3. 新しい編集を確認し、それぞれ **Keep** または **Undo** を選択します。
4. エージェントの方針が希望と異なる場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加の指示を送ります。

> [!TIP]
> 進行中のセッションを誘導するほうが、最初からやり直すより短時間で済みます。追加プロンプトで調整を依頼できます (例: 「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」)。また、方向を修正できます (例: 「3 つ目の切り替えを追加せず、既存の設定パネルにライト モードを統合してください」)。作業範囲の拡張もできます (例: 「両方の切り替えにキーボード ショートカットも追加してください」)。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルをすべて確認します。Astro コンポーネント、スタイル、関連テストなどが含まれているはずです。
3. いくつかのファイルを開いて差分を確認します。カスタム エージェントのアクセシビリティ パターン (ARIA 属性、キーボード操作、セマンティック HTML、local storage への保存) が反映されていることを確認します。
4. 内容に問題がなければ **Source Control** パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat のエージェント モードで進行中のセッションを監視、誘導し、ファイル編集を確認して受け入れまたは却下し、コンテキストを保ったまま追加プロンプトで作業を拡張しました。

このレッスンでは、エージェントの作業をリアルタイムで監視し、個別のファイル編集を受け入れまたは却下し、追加プロンプトでセッションを誘導する方法を学びました。
